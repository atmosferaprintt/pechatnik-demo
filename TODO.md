# Отложенные задачи — CRM «ПЕЧАТНИК»

Всё, что «надо сделать потом» — складывается сюда.
Добавляется по команде пользователя **«Запланируй задачу на будущее»**.

## Формат

```
### YYYY-MM-DD · 🔴/🟡/🟢 · Краткое название
**Контекст:** почему задача появилась, какая проблема
**Что сделать:** конкретные шаги
**Блокеры / зависимости:** что мешает сделать сейчас
**Ориентир по времени:** 15 мин / 1 час / полдня
```

Приоритеты:
- 🔴 высокий — безопасность / потенциальная потеря данных / блокирует работу
- 🟡 средний — улучшения надёжности / UX / накопленный техдолг
- 🟢 низкий — nice-to-have / косметика

Самые свежие — снизу (хронологический порядок добавления).

## Задачи

### 2026-07-17 · 🟢 · Перетаскивание задач и заметок на тач-экранах (телефон/планшет)
**Контекст:** на доске задач и в «Заметках» (с 2026-07-19) перетаскивание сделано через HTML5 drag-and-drop — на тач-экранах эти события не срабатывают, работает только мышью/трекпадом.
**Что сделать:** тач-вариант через pointer events (долгое нажатие → тянуть карточку), с теми же dropInCol/dropOnGrid/sort_order.
**Блокеры / зависимости:** нет; сначала посмотреть, пользуются ли доской с телефона вообще.
**Ориентир по времени:** 1–2 часа

### 2026-07-24 · 🟡 · Сайт типографии на pechatnik-cherkessk.ru
**Контекст:** домен куплен и работает (CRM на поддомене crm.), корень pechatnik-cherkessk.ru указывает на бегет-хостинг и пустует — решение Рабии 2026-07-24: делаем сайт-визитку типографии.
**Что сделать:** (1) варианты каркаса `сайт-variants.html` — показ Кристи через GitHub Pages (сделано в этот же день, ждём выбора); (2) после выбора — свёрстанный сайт (статичный HTML, без сборки), контент от Кристи: телефон, адрес, часы, фото работ, цены; (3) хостинг: либо public_html бегет-хостинга (корень уже смотрит туда), либо перевести корень на VPS и раздавать через Caddy.
**Блокеры / зависимости:** выбор варианта Кристи; реальные контакты/фото от неё.
**Ориентир по времени:** каркасы — полдня; финальный сайт — 1–2 дня после контента.

### 2026-08-13 · 🟢 · Возвраты в Аналитике: вычитать из выручки, а не показывать расходом бизнеса
**Контекст:** возврат клиенту (отказ от заказа) записывается расходом категории «Возврат». Прибыль за месяц при этом верная (доход +7 000 и расход +7 000 гасят друг друга), но выручка завышена на сумму возврата и в «Расходах бизнеса» висит статья, которой по факту не было. Кристи 2026-08-13: «кривость в аналитике не страшна» — правку отложили, чтобы не менять задним числом привычные цифры и Excel-выгрузку.
**Что сделать:** в [Analytics.jsx](src/sections/Analytics.jsx) вычитать расходы категории «Возврат» из `opIncome` и исключать их из `expense`/разбивки по категориям (helper `isRefundCat` уже есть в [taskMoney.js](src/taskMoney.js)); то же самое в Excel-экспорте — строка «ВОЗВРАТЫ» под доходами. Кассу дня не трогать: деньги физически ушли.
**Блокеры / зависимости:** делать, только когда возвратов станет заметно много (или Кристи сама попросит) — цифры прошлых месяцев после правки поедут.
**Ориентир по времени:** ~1 час

### 2026-07-17 · 🟡 · Баннер «вышло обновление» при новом деплое
**Контекст:** CRM — одностраничник; девочки держат вкладку открытой весь день и после деплоя сидят на старой версии, пока не обновят страницу руками (из-за этого «менеджера видят оплаты друг друга» уже после фикса).
**Что сделать:** при сборке класть в dist версию (хеш коммита) файлом `version.json`; клиент по фокусу вкладки/раз в N минут сравнивает со своей и показывает жёлтый баннер «Вышло обновление — нажми, чтобы обновить» (клик = location.reload()).
**Блокеры / зависимости:** нет.
**Ориентир по времени:** ~1 час
